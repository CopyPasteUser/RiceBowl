for RiceBowl on Linux Mint/XFCE. It is not a release claim. Local fixes
listed below require virtual-X11 CI and physical acceptance; entries are
not closed merely because a headless regression passes.

[PR #69](https://github.com/CopyPasteUser/RiceBowl/pull/69) with passing
virtual-X11 CI, but **real-machine acceptance remains open**. Reports below

## Recommended execution order

1. **Restore core interaction:** QA-07, QA-11, QA-10 and QA-02. Preserve
   before/after pointer recordings and check that menu focus and popovers do
   not collapse when moving from the launcher/taskbar to the opened surface.
2. **Unblock safe updates:** QA-09. First inspect the dirty working tree and
   distinguish generated/managed files from real user edits; require an
   explicit choice before stash, commit or conflict resolution.
3. **Fix window management and anchors:** QA-05, QA-08. Re-test existing
   shared native-window promises on Mint rather than treating CI as proof of
   laptop behavior.
4. **Expand coherent styling:** QA-04, QA-06 and QA-03. Keep system-owned and
   application-owned window content separate; prioritize functionality ahead
   of a broad visual overhaul.
5. **Broaden application coverage:** QA-01 as a cross-rice roadmap track.
   A shared, compatible styling/integration layer is preferable to one-off
   patches for each proprietary toolkit.

## Reproduction and evidence gate

- Record installed RiceBowl Git SHA, current rice and `XDG_SESSION_TYPE`.
- Note whether the issue occurs immediately after a fresh login/restarted
  shell, and whether XFWM4 and the relevant backends are present.
- Capture a short pointer recording or screenshot for QA-02, 05, 07, 08,
  10 and 11; capture the **exact updater status and changed file paths** for
  QA-09 without dumping secrets, diffs, or private file contents.
- Reproduce, write a focused regression, fix and re-run affected native GTK/X11
  tests before marking an item implemented. Actual-device signoff is separate.

## Scope decisions retained

- macOS Aurora stays unchanged unless the owner explicitly asks for changes.
- **No riceExplorer integration before riceExplorer 1.0.** Existing file-manager
  behavior and Thunar fallback remain in place.
- Keep the README concise. Detailed acceptance items live here and in the
  individual rice roadmaps; use status links instead of burying the README
